# HTML Downloader -- 要件定義書

## 1. このシステムは何であるか

ユーザーが現在閲覧しているWebページを、ローカルファイルとして保存するためのChrome拡張機能である。

### 1.1. 存在目的

「今見ているページを、今すぐ、手元に残す」という単一の行為を、最小の摩擦で完遂させること。

### 1.2. 対象ユーザー

- Webページのソースや構造を一時的に保持したい開発者
- 特定のページの状態をアーカイブとして残したいリサーチャー

---

## 2. 何を何で実装するか(採用判断)

### 2.1. ページ保存 -- Chrome Extension APIs

| 要素           | 採用技術                         | 根拠                                                                                                                          |
| -------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| DOM取得        | `chrome.scripting.executeScript` | activeTab権限のみで動作する最小権限アプローチ。Content Scriptの常駐を不要とし、ユーザーがクリックした瞬間だけコードを注入する |
| 完全アーカイブ | `chrome.pageCapture.saveAsMHTML` | ブラウザ自身がレンダリング済みリソースをMHTMLにパッケージするため、外部ライブラリ不要で信頼性が最も高い                       |
| ファイル保存   | `chrome.downloads.download`      | OS標準のダウンロードマネージャーへ委譲する。保存先の選択・重複ファイル名の処理等をブラウザに一任できる                        |
| 保存後のUX     | `chrome.downloads.show`          | ダウンロードしたファイルをエクスプローラー上でハイライト表示する。ブラウザネイティブの挙動であり追加の権限を必要としない      |

### 2.2. UI -- Popup Architecture

| 要素     | 採用技術                        | 根拠                                                                                           |
| -------- | ------------------------------- | ---------------------------------------------------------------------------------------------- |
| UI構造   | `popup.html` (静的HTML)         | ポップアップは「開いて、選んで、押す」の3秒で完結する。SPAフレームワークは不要                 |
| スタイル | Vanilla CSS (`style.css`)       | コンポーネント数が5未満の規模において、CSSフレームワークの導入は依存対効果が負になる           |
| ロジック | Vanilla JavaScript (`popup.js`) | Chrome Extension APIとの直接対話が主務であり、状態管理ライブラリが解決すべき複雑性が存在しない |

### 2.3. 権限モデル -- 最小権限の原則

| 権限          | 必要性                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------- |
| `activeTab`   | ユーザーがクリックした瞬間のタブにのみアクセスする。`<all_urls>` を回避するための意図的選択 |
| `scripting`   | `executeScript` でDOM取得スクリプトをワンショット注入するために必要                         |
| `downloads`   | ファイル保存とダウンロード後のフォルダ表示に必要                                            |
| `pageCapture` | MHTML形式でのページ全体保存に必要                                                           |

## 3. 何を何で実装しないか(排除判断)

### 3.1. スクレイピング機能 -- 排除

**何を**: ページ内の特定要素の抽出、CSSセレクタによるフィルタリング、複数ページの巡回取得。

**なぜ排除するか**: 本ツールの目的は「ページ全体の保存」であり、「ページの解析」ではない。スクレイピング機能を加えた瞬間、UIにセレクタ入力欄・プレビュー・結果表示が必要になり、ポップアップの「3秒完結」という設計原則が崩壊する。専用のスクレイピングツール(DevTools, Puppeteer等)が既に存在する領域に踏み込む理由がない。

### 3.2. Background Service Worker -- 排除

**何を**: バックグラウンドでの定期保存、スケジュール実行、ページ変更の監視。

**なぜ排除するか**: Service Workerを導入するとメモリ常駐のライフサイクル管理が必要になり、「ユーザーがクリックした時だけ動く」という設計の単純さを失う。定期保存はブラウザのブックマーク機能やWebアーカイブサービスの責務である。

### 3.3. 外部リソースの個別ダウンロード -- 排除

**何を**: 画像・CSS・JSファイルを個別にフェッチし、相対パスを書き換えてローカルに再構成する方式。

**なぜ排除するか**: CORS制約・認証付きリソース・動的生成されたスタイル等、エッジケースが無限に存在する。`pageCapture` APIがブラウザレベルでこの問題を解決済みであるため、アプリケーション層で再発明する理由がない。「HTMLのみ」モードが外部リソースを含まないのは仕様であり、制限ではない。

### 3.4. クラウド同期・外部サービス連携 -- 排除

**何を**: 保存したファイルのクラウドストレージへの自動アップロード、Google Drive / Dropbox連携。

**なぜ排除するか**: 外部サービスとの連携はOAuth認証フロー・API Key管理・ネットワーク障害ハンドリングを要求する。これは「ローカルに保存する」という本ツールのスコープを逸脱する。ユーザーが保存後にクラウドへ同期したい場合、OSレベルの同期クライアント(Google Drive for Desktop等)が既にその責務を担っている。

### 3.5. CSSフレームワーク / JSフレームワーク -- 排除

**何を**: TailwindCSS, Bootstrap, React, Vue 等の導入。

**なぜ排除するか**: UI要素がボタン2個・ラジオボタン2個・テキスト表示1個の規模において、フレームワークのランタイムサイズ・ビルドステップ・学習コストのいずれもが、得られるメリットを上回る。Vanilla CSS/JSで十分に表現可能であり、ビルドツールなしでChromeにそのまま読み込める即時性を維持する。

### 3.6. 自動テストスイート -- 排除(現時点)

**何を**: Jest / Playwright等によるユニットテスト・E2Eテスト。

**なぜ排除するか**: Chrome Extension APIはブラウザランタイムでのみ動作し、Node.jsでのモックは本質的にAPIの挙動を再現できない。ファイル総数4、ロジック80行のコードベースに対して、テスト基盤の構築コストが品質保証の効果を大幅に上回る。手動検証で十分にカバー可能な規模である。

## 4. 設計原則

| 原則         | 具体的な制約                                                              |
| ------------ | ------------------------------------------------------------------------- |
| **単一目的** | 「ページを保存する」以外の機能を持たない                                  |
| **最小権限** | `<all_urls>` や `host_permissions` を使用しない                           |
| **ゼロ依存** | npm, node_modules, ビルドステップを持たない                               |
| **即時性**   | 操作開始からファイル保存完了まで3秒以内を目標とする                       |
| **非常駐**   | Background Service Workerを持たない。ユーザーアクションの瞬間のみ動作する |

## 5. スコープ境界の図示

```
                 +-------------------------------------+
                 |         HTML Downloader              |
                 |                                     |
  ユーザー       |  [クリック] -> [DOM/MHTML取得]       |
  クリック  ---->|         -> [Blob生成]               |
                 |         -> [ダウンロード]            |     ファイル
                 |         -> [完了通知]         ------+----> (.html / .mhtml)
                 |                                     |
                 +-------------------------------------+
                           ここまでが責務
                 - - - - - - - - - - - - - - - - - - - -
                           ここから先は対象外

                 x スクレイピング / 解析
                 x クラウド同期
                 x 定期実行 / 監視
                 x 外部リソース個別取得
```
